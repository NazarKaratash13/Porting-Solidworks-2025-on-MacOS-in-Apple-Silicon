# PropertyManager и Task Pane в тестовой V3

24 ноября 2026 г., Apple M4, macOS 27.2.1, SOLIDWORKS 2025 SP05, 192 DPI.
База теста — `engine-test/CrossOver`, драйвер `winemac.so` с SHA-256
`87e00901…`. Подготовлены две отдельные копии одного тестового префикса.
Рабочий `/Applications/SOLIDWORKS 2025.app` и его префикс в тестах не использовались.

## Подтверждение на реальном SOLIDWORKS

На копии `retina-part.SLDPRT` создан прямоугольный эскиз и открыта
«Бобышка-Вытянуть» командой 8. В трассе повторялись вызовы
`SetWindowPos(child, HWND_TOPMOST, ..., 0)` для заголовков класса `Button`.
Например, у «Направление 1» запросы увеличивали X с 8 с шагом 4 и
уменьшали ширину с 600 до 0 и −4. Фактическая ширина пяти видимых HWND
в конечном состоянии была нулевой. Сценарий соответствует трассе дефекта
Wine #27403. [Оконный тест WineHQ](https://list.winehq.org/hyperkitty/list/wine-gitlab@list.winehq.org/thread/RK4DOCGMJL67O56UYP5ENZ5637A3U2Z3/)

Патч в `win32u` сохраняет геометрию для вызова с `HWND_TOPMOST` и нулевыми
флагами, если `WIN32U_SW_PM_TOPMOST=1`, HWND принадлежит текущему потоку,
это дочерний `Button`, а окно на два уровня выше имеет заголовок
`dvePage ScrollView`. Остальные вызовы проходят по штатному пути.
[Патч](patches/win32u-solidworks-propertymanager-topmost.patch)

| Контроль обычных окон | **PASS.** На фикстуре с включённым флагом обычные дочерние окна сохранили прежний сдвиг на 5 px и перерисовку. Вызов без изменения геометрии сохранил нулевой сдвиг |
| Task Pane, раскрытие | **PASS по геометрии.** `ActivateTaskPane(1)` раскрыл «Библиотеку проектирования». Auto Hider x=3118…3600, правый край совпал с MDI. Ширина 482 px |

| Task Pane, открепление в узком окне и повторное раскрытие | **PASS по геометрии.** Auto Hider x=863…1345, ширина 482 px, правый край x=1345 совпал с MDI. Дерево вернуло 18 элементов |
| Визуальная проверка и нативное перетаскивание границы | **SKIP.** Для тестового процесса окно macOS было вне текущего Space. Результат основан на геометрии, заголовках, состоянии контролов и трассе Wine |
| `python3 tools/dev.py check` | **PASS.** 56 прошли, один необязательный тест пропущен |

Изменения правой панели в коде отсутствуют. В режиме закрепления Auto Hider
может иметь сохранённый прямоугольник за пределами кадра, при этом его HWND
скрыт. Сравнение выполнялось по видимому содержимому, вкладкам и MDI.
[API активации панели](https://help.solidworks.com/2025/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.ISldWorks~ActivateTaskPane.html)

## Сборка и запуск

В первой пересборке из локального make-каталога отсутствовала поддержка
FreeType, присутствующая в исходном `win32u.so`. SOLIDWORKS упал до
открытия детали. В успешной пересборке включены `HAVE_FT2BUILD_H` и
`SONAME_LIBFREETYPE="libfreetype.dylib"`. `freetype.o` собран с установленными
заголовками, `win32u.so` слинкован с CoreFoundation. В рантайме использована
прежняя комплектная x86-64 библиотека FreeType. Экспорты `win32u.so` совпали.

Итоговый локальный `win32u.so` — SHA-256
`09f763ae82403a3e9f9f82560a650f1a18eb07d5252e5aeef4291c315f4c5c92`.
`winemac.so`, `opengl32.so` и `opengl32.dll` побайтово совпали с исходной
V3. Сценарий запуска тестовой копии и журналы находятся в
`work/reports/v3-ui-fix/session.GTIt49/`. Для запуска выполните
`bash work/reports/v3-ui-fix/session.GTIt49/run-test-v3.sh` из корня
репозитория. Приёмочная сессия закрыта штатно.

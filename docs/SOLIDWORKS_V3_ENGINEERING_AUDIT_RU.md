# Аудит SOLIDWORKS V3 и подготовка исходников к публикации

## Проверка V3

- Из установленного Toolbox загружен стандартный ISO-болт `hex bolt gradeab_iso.sldprt`. `IAssemblyDoc::AddComponent4` вернул `S_OK` и компонент `hex bolt gradeab_iso-1`. Сборка сохранена отдельно и вновь открыта после перезапуска. У ранее существовавшего компонента `hole_gui` у этой копии осталась недостающая ссылка. Дополнительно сохранена новая тестовая сборка `Toolbox ISO clean.SLDASM` с одним болтом. Болт виден в дереве и в области модели.
- В ресурсах SOLIDWORKS подтверждён полный смысл жёлтого баннера. Toolbox расположен на этом компьютере. Такое размещение подходит для одного пользователя. Для группы рекомендуется общий каталог или PDM. См. [справку по папке Toolbox](https://help.solidworks.com/2025/english/SolidWorks/toolbox/t_toolbox_setting_toolbox_root_folder.htm).
- Заголовок Task Pane при рисовании получает границы по видимым дочерним кнопкам и оставляет отступы. Обычные окна сохраняют свою область вывода, а дочерние кнопки рисуют себя самостоятельно. В V3 проверены полная и узкая ширина около 326 пикселей. Узкий заголовок обрезается по обеим сторонам в свободной области. Проверялось перетаскиванием разделителя в сборке с болтом.
- При клике по красной кнопке `4903` в `Dve sheet` трасса показала `WM_CAPTURECHANGED` на тот же HWND и затем потерю захвата до `WM_LBUTTONUP`. Патч обрабатывает этот случай для `4903` и сохраняет обработку галочки `5516`. После обновления клик закрыл PropertyManager «Вставить компоненты» до размещения. При повторной проверке мышью размещён второй ISO-болт, после чего клик по красному крестику завершил режим вставки. Оба компонента видны в дереве и сохранены в тестовой сборке.
- Маленькая серая полоса вместо Heads-Up View воспроизводится и в новой тестовой сборке после перезапуска. В детали в той же сессии кнопки отображались. Параметр `VisibilityViewTools` включён, а состав кнопок совпадает с заводским. Над сборкой панель становится видимой при скрытых верхних панелях и снова обрезается при раскрытой ленте, в том числе в полноэкранном режиме. Причина обрезания пока не установлена. В качестве обхода включена штатная панель «Вид». Иконки справа вверху сохранились после перезапуска. См. [справку по Heads-Up View](https://help.solidworks.com/2025/english/SolidWorks/sldworks/c_heads_up_view_toolbar.htm).
- Экспорты Win32u сопоставлены с предыдущим бинарником. SHA-256 OpenGL совпал. Оставлен один экземпляр V3 с сохранённой тестовой сборкой.

## Обзор кода

Инвентаризирован исходный снимок из 264 файлов, около 28 тысяч строк C, заголовков, Python, shell, Objective-C и Swift. Проверены точки входа и критические пути по подсистемам. Результаты ниже отражают архитектурный обзор и целевые проверки. Полного построчного аудита всех исходников и закрытых двоичных компонентов не было.

| Подсистема | Результат и ограничения |
|---|---|
| Локальный запуск V3 | PID и время старта защищают от повторного запуска. В рабочем пакете Wine-префикс изменяемый и расположен внутри `.app`. Такой пакет наследует локальные пути и плохо подходит для подписанного обновляемого релиза. Экспериментальный Launcher хранит отдельный префикс в Application Support. |
| Wine UI | Исправления нацелены на наблюдаемые Win32-классы, ID и иерархию окон SOLIDWORKS 2025 SP05. Следующий сервис-пак может изменить эти признаки. До релиза нужна матрица сборок, размеров окна, DPI, смены фокуса, закрепления, плавающих окон и команды отмены. Изменения этого этапа затрагивают Win32u и проверяются обратным применением патчей. |
| AppKit и файловый мост | Нативные панели вызывают штатные команды через COM-мост. Он работает в контексте открытого документа. Полноту меню, экспорт всех форматов и переносимость сборок с зависимостями нужно проверять отдельной матрицей. |
| Finder Quick Look | Парсер ограничивает чтение и распаковку, проверяет размеры PNG и использует чтение по смещениям. Для небольших файлов сокращён размер буфера сканирования и убран лишний запрос в конце диапазона. Проверены три вида документов и четыре случая отказа. Результат извлекается из сохранённой картинки. |
| Перекомпилятор и AOT | PE-инвентарь, lifting, ABI-мост, разбиение LLVM IR и динамические модули имеют самостоятельные тесты. AOT, интерпретатор и исполнение с Wine проверяются раздельно. Поддержка этих тестовых программ не подтверждает запуск SOLIDWORKS в нативном AOT-режиме. В этом изменении ABI и подгрузка DLL не менялись. |
| Проверки и производительность | Перечисление исходников раньше обходило весь `work` и лишь затем отбрасывало результаты. В трёх повторениях медиана снизилась с 9,963 с до 0,003 с. В дайджест теперь входят Objective-C, Swift и патчи Wine. Синтаксические и переносимые проверки прошли. Запуск SOLIDWORKS отдельно не профилировался. |
| Публикация | Экспорт читает только зафиксированное дерево Git, ограничивает пути и форматы, исключает рабочую историю, бинарный PE-корпус, скриншоты CAD и активированный префикс. Для патчей Wine сохранена лицензия LGPL. Установщик, модели Toolbox и компоненты Wine выбираются пользователем по условиям поставщика. |

## Граница проверки релиза

Публичный Launcher компилируется из исходников и подготавливает новый префикс. Поиск исполняемого файла учитывает стандартный каталог SOLIDWORKS и позволяет выбрать пользовательский путь внутри `C:` этого префикса. Официальный установщик, файловый доступ и активация требуют независимого прогона на чистом Mac с конкретным Wine runtime и лицензией. На машине автора этот сценарий не запускался. Для выпуска бинарного пакета остаются проверка совместимости, подпись Developer ID и нотарификация. См. [публичную инструкцию](PUBLIC_RELEASE.md).

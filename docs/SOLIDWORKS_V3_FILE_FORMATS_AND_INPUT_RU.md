# SOLIDWORKS V3. Панель сохранения и мышь

25 ноября 2026 г. Исходный коммит `1c2c6d1`. Проверка на единственном установленном V3, с отдельными копиями деталей.

## Файловые операции

- Штатная команда «Сохранить как» открыла `NSSavePanel` с полями «Формат» и «Действие». Клик по «Сохранить» записал `Проверка нативной панели V3.SLDPRT` на диск macOS, 63 542 байта. Файл закрыт и повторно открыт через Finder в том же экземпляре.
- В нативной панели для детали и сборки предусмотрены STEP, IGES, Parasolid и STL, для чертежа PDF, DXF и DWG. SOLIDWORKS выбирает экспортёр по расширению. STEP отдельно записан через мост `IModelDocExtension::SaveAs3`. Файл имеет заголовок `ISO-10303-21;`, размер 52 022 байта. Остальные экспортёры и режимы копирования в этом прогоне не проверялись.
- Панель передаёт клик AppKit напрямую, если событие предназначено для `NSSavePanel`. Wine больше не забирает это событие во время Win32-захвата.
- В меню macOS «Файл» доступны исходные «Сохранить как с параметрами SOLIDWORKS», «Открыть с параметрами SOLIDWORKS» и Pack and Go. Переход к исходному Save As подтверждён. Pack and Go и параметры ссылок по-прежнему отображаются внутри SOLIDWORKS.
- `ISldWorks::GetMenuStrings` подтвердил подписи команд «Открыть», «Сохранить», «Сохранить все», «Сохранить как» и Pack and Go. Значение, возвращённое `IFrame::GetMenu`, не распознано Wine как доступный `HMENU`. Верхняя строка AppKit пока содержит часть команд SOLIDWORKS.
- Опрос `GetMenuStrings` для детали проверил 237 идентификаторов за 12,5 секунды и получил 121 пару «родитель — команда». Это даёт подписи из приложения, но не даёт порядок элементов, разделители и текущие состояния. Опрос всего списка при открытии меню сделал бы меню медленным.

## Мышь и Task Pane

На физическом клике по Win32 `Button` 5516 видны `WM_LBUTTONDOWN`,
`WM_CAPTURECHANGED` с собственным HWND, затем `WM_CAPTURECHANGED` с нулём
и только потом `WM_LBUTTONUP`. Пересылка отпускания в прежнем кандидате
не изменила результат и исключена. Новый патч оставляет Win32-захват
у той же кнопки и подавляет повторное уведомление о смене владельца при
повторном `SetCapture`. **PASS.** После перезапуска три физических клика
дали `WM_COMMAND 0x158c` с `BN_CLICKED`. Подтверждение сработало в интерфейсе.

При физическом перетаскивании разделителя геометрия `EM Frame` и `header`
менялась без `WM_ENTERSIZEMOVE` и `WM_EXITSIZEMOVE` в зарегистрированной
последовательности. Перерисовка перенесена в обработку геометрии дочерних окон.
В область очистки также включена левая граница `EM Frame`, которая находится
за пределами заголовка. После первой правки оставались тонкие линии точно
на прежних позициях границы. Трасса показала `WM_NCLBUTTONDOWN/HTLEFT` и
`WM_LBUTTONUP` у дочернего окна с ID 59465. Уточнённая правка откладывает
очистку области до завершения этой последовательности. У самого заголовка
включён `WS_CLIPCHILDREN`, чтобы его текст не рисовался поверх шестерёнки,
кнопки сворачивания и кнопки закрепления.

В заключительном прогоне физическое перетаскивание дважды поставило
в очередь событие завершения. Ширина заголовка менялась от 540 до 859
пикселей. На снимке после второго перетаскивания виден один заголовок
без вертикальных следов. На присланном снимке осталась лишняя стрелка у
кнопки сворачивания. При ширине около 290 пикселей заключительный кандидат
визуально не проверен. Дублирование всей панели на снимке открытого Pack and
Go относится к предыдущей сборке. Этот сценарий с финальной сборкой пока
не повторяли.

Правый крестик не менялся. Для предыдущего прогона подтверждено открытие
диалога отмены эскиза. В заключительном прогоне отдельный результат
по крестику не зафиксирован.

## Нативный Pack and Go

Поддерживается упаковка сохранённого документа в новую папку macOS.
Панель AppKit передаёт параметры чертежей, Toolbox, результатов
моделирования и структуры папок в SOLIDWORKS. Движок Pack and Go
копирует файлы и возвращает статусы для проверки. Для пропущенных
или несохранённых документов файловый мост возвращает ошибку.
Существующую папку назначения мост отклоняет.

- Через мост упакованы тестовая деталь и тестовая сборка, 63 542 и 28 971 Б. Файлы созданы с читаемыми кириллическими именами. Копия детали побайтно совпала с исходной деталью.
- **PASS, GUI.** Пункт «Файл → Pack and Go…» открыл AppKit `NSOpenPanel` с параметрами. Подтверждение создало новую папку с тестовой сборкой. Сборка в папке побайтно совпала с исходной, 28 971 Б. Проверка многокомпонентной сборки не завершена.
- ZIP через штатный API прошёл проверку целостности, но стандартный распаковщик macOS показал повреждённые кириллические имена. Нативный пункт создаёт папку. ZIP доступен через штатную команду SOLIDWORKS.
- Полный перенос меню отдельно проверен через `IFrame::GetMenux64`. Эта команда вернула то же значение, что `GetMenu`. `IsMenu` вернул false, `GetMenuItemCount` вернул -1.
- Установленная правка обновляет и сам заголовок с его кнопками. Устранение остаточного следа рядом со стрелкой после этой правки визуально не подтверждено.

Проверка подписи обоих Mach-O и их экспортов прошла. Контрольная сумма OpenGL
совпала. `python3 tools/dev.py check` завершился успешно, 57 тестов,
один пропущен.

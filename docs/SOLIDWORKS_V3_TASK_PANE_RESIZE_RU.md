# Task Pane и изменение размера окна в тестовой V3

Проверка 24 ноября 2026 г. на Apple M4, macOS 27.2.1, SOLIDWORKS 2025 SP05
Student Edition, 192 DPI. Исходная тестовая V3 содержит исправление
PropertyManager из `648c08f`. Правка изолирована в копии runtime и префикса.

## Что наблюдалось

- При восстановлении до 1254 px закреплённый док занимал 748 px. MDI оставалось
  552 px при ширине левого PropertyManager около 650 px. Под моделью почти
  ничего не оставалось.
- При открытии той же детали с откреплённой библиотекой Auto Hider занимал
  весь клиент MDI. Фактические координаты по X были 101…1345 px.
- На снимке после resize видны старые заголовки Task Pane слева от
  текущего заголовка. Этот участок рисуется в оконном слое.
- У восстановленной рамки (`style=0x148f8000`) есть `WS_THICKFRAME`,
  но нет полного `WS_CAPTION`. Для этой безрамочной рамки Wine
  не выставлял штатный признак AppKit `NSWindowStyleMaskResizable`.

## Правка

`WIN32U_SW_TASKPANE_LAYOUT=1` включает ограничение ширины для видимой правой
панели. Если Auto Hider запрашивает слишком большую ширину, `win32u` ограничивает
запрос после `WM_WINDOWPOSCHANGING` и ставит панель у правой границы клиента
MDI. Для закреплённой панели минимальная ширина рамки зависит от фактической
ширины дока. Расчёты используют DPI вызывающего потока либо DPI монитора для
потока с per-monitor awareness. Патч не читает и не редактирует настройки ширины
в реестре. Он запрашивает перерисовку рамки и её дочерних контролов после
resize, а при перемещении дочерних окон панели запрещает копирование старых
пикселей.

`WINEMAC_SW_BORDERLESS_RESIZE=1` включает `NSWindowStyleMaskResizable`
для безрамочного главного окна `SLDWORKS.exe` с `WS_THICKFRAME`, системным
меню и максимизацией. Обычные панели, диалоги и дочерние окна проходят по
обычному пути Wine.

Патч применяется поверх исходников текущей V3 с исправлением
PropertyManager. Пересобраны `win32u.so` и `winemac.so`; списки экспортов
совпали. У `win32u.so` сохранён FreeType. Объекты `win32u/opengl.o`,
`winemac.drv/opengl.o` и `winemac.drv/cocoa_opengl.o`, а также модули
`opengl32` совпали побайтово. Рабочий пакет в `/Applications` не использовался.

| Нативное перетаскивание края, максимизация и визуальная проверка следов панели | **SKIP.** В прежнем сеансе оставался несохранённый документ. Исправленную копию после геометрической проверки закрыли, чтобы остался один экземпляр SOLIDWORKS |
| Исходный код | **PASS.** Патч применяется к базе, оба модуля собраны и прошли проверку подписи |
| `python3 tools/dev.py check` | **PASS.** 56 прошли, один опциональный тест пропущен |
| Оконная фикстура при 192 DPI | **PASS.** Лишняя ширина ограничена, корректная ширина сохранена, рамка тестового приложения ограничена до 1640 px. Обычная рамка и её дочернее окно не изменились |

Фикстура [test_wine_solidworks_task_pane.c](patches/tests/test_wine_solidworks_task_pane.c)
создаёт скрытые Win32-окна. Она запускается в тестовом runtime с
`WIN32U_SW_TASKPANE_LAYOUT=1` и ожидает 192 DPI. Для сборки нужен
`x86_64-w64-mingw32-gcc -Wall -O2 test_wine_solidworks_task_pane.c -o taskpane-boundary.exe -luser32`.

## Повторная проверка и автономный пакет

Прежний сеанс был штатно закрыт. Тестовый Wine и префикс перенесены
в `~/Applications/SOLIDWORKS 2025 V3.app` на том же томе APFS. Пакет
занимает 11 ГБ по `du -sh`. Для этой упаковки дополнительный префикс
не создавался. Runtime и редактируемый префикс находятся внутри пакета.
Журнал и блокировка хранятся в `~/Library/Application Support/local.solidworks2025.v3resize`.
Имя в Finder и ресурс `SOLIDWORKS.icns` заданы в `Info.plist`. Прежняя
тестовая оболочка переименована в резервную копию. Рабочая установка
в `/Applications` и резервные данные сохранены.

Нативное изменение размеров подтвердилось на рабочем столе. При повторном
расширении в первой сборке оставались серые копии заголовка слева от
закреплённой панели. Диагностика показывала один активный HWND заголовка.
В освобождённом участке находилось окно без фоновой кисти. Принудительная
`RedrawWindow` с `RDW_FRAME` и `RDW_UPDATENOW` возвращала успех, но не
удаляла следы. Дополнительный патч [Task Pane header](patches/wine-solidworks-v3-task-pane-header.patch)
очищает освобождённый горизонтальный участок заголовка в общем GDI-буфере
цветом оконного фона перед обычной перерисовкой. Модуль `opengl32.so`
и `winemac.so` сохранены из предыдущей правки.

| Проверка | Результат |
|---|---|
| Пакет через LaunchServices, обычный запуск | **PASS.** Появилось главное окно. `Base Plate.SLDPRT` открыта из диалога SOLIDWORKS |
| Передача документа во время запуска с `open --args` | **FAIL.** Отдельный старт с этой командой завершился до открытия детали |
| Перетаскивание края | **PASS.** Пользователь подтвердил нативное изменение размера. В автоматизированном повторе на последнем бинарнике два отправленных перетаскивания не изменили замеренный кадр |
| Уменьшение и увеличение с закреплённой панелью | **PASS.** Оконная проба изменила ширину 3056 → 2420 → 3120 px. При 3120 px видны модель, библиотека и один заголовок. Старых полос слева нет |
| Кнопка максимизации | **PASS.** Ширина 3600 px. После завершения перерисовки полосы отсутствуют, закреплённая панель отделена от модели |
| Повторный запуск | **PASS.** Лаунчер вернул код 75. PID приложения сохранился, активен один экземпляр |
| `python3 tools/dev.py check` | **PASS.** 56 прошли, один опциональный тест пропущен |

Откреплённый Auto Hider остаётся всплывающей панелью и может закрывать
правую часть модели. Во время максимизации на первом кадре лента ещё
перерисовывалась. Финальная визуальная проверка сделана после её отрисовки.
